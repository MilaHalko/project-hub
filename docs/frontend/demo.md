# Показ Project Hub — сценарий

Показ 16.11.2026, локально: веб-приложение и Swagger.
Скриншоты каждого шага лежат в [`demo/`](demo/). Их снимает скрипт `demo/walk.mjs`.

Короткий словарь (термины ниже встречаются часто):

- **API** — серверная часть на FastAPI. Отвечает на HTTP-запросы JSON-ом.
- **JWT (токен)** — подписанная строка «я такой-то пользователь». Её выдаёт `POST /login`, браузер шлёт её в заголовке `Authorization: Bearer …`. Живёт 1 час.
- **Swagger** — страница `/docs`, которую FastAPI строит сам по коду. Там можно вызвать любой эндпоинт руками.
- **Эндпоинт** — один адрес API с методом, например `GET /projects`.
- **Docker Compose** — запускает все части проекта (API, база, S3, веб) одной командой.
- **moto** — локальная подделка Amazon S3, хранит файлы в памяти. Нужна, чтобы не ходить в настоящий AWS.
- **nginx** — веб-сервер в контейнере `web`: раздаёт собранный React и пересылает `/api/…` в API.

## 0. Перед показом (5 минут)

### Адреса

| Что | Адрес |
|---|---|
| Веб-приложение | <http://127.0.0.1:8100/> |
| Swagger | <http://127.0.0.1:8020/docs> |
| API напрямую | <http://127.0.0.1:8020/health> → `{"status":"ok"}` |

Swagger открывать только по адресу `:8020/docs`. Через веб (`:8100/api/docs`) он не работает: nginx не пускает внешние скрипты (это правило безопасности CSP).
Swagger грузит свои скрипты из интернета (cdn.jsdelivr.net), значит для него нужен интернет. Веб-приложению интернет не нужен.

### Логины

| Логин | Пароль | Что у него есть |
|---|---|---|
| `anna` | `anna1234` | владелец «Дипломный проект» (там участник boris) и «Сайт кофейни»; участник в «Поездка в Карпаты» |
| `boris` | `boris1234` | владелец «Поездка в Карпаты» (там участник anna); участник в «Дипломный проект» |
| `vera` | `vera12345` | без проектов: её приглашаем вживую |

Это демо-пароли только для локального стенда.

### Команды

Все команды запускать из корня репозитория, на свежем `main` (`git pull`).
Стенд работает под своим именем `demo`, поэтому другие стенды и их данные не трогает.

Запуск (первая сборка 2–3 минуты):

```bash
APP_DB_PORT=55450 APP_S3_PORT=55451 APP_PORT=8020 WEB_PORT=8100 APP_JWT_SECRET=$(openssl rand -hex 32) docker compose -p demo -f docker-compose.yml -f frontend/compose.yml up -d --build --wait
```

Заполнить демо-данными (только через API; повторный запуск ничего не дублирует):

```bash
python3 docs/frontend/demo/seed.py --documents
```

Проверка:

```bash
curl -s http://127.0.0.1:8020/health
```

Остановить:

```bash
docker compose -p demo -f docker-compose.yml -f frontend/compose.yml down
```

Сбросить всё начисто (удаляет только данные стенда `demo`), потом снова «Запуск» и «Заполнить»:

```bash
docker compose -p demo -f docker-compose.yml -f frontend/compose.yml down -v
```

Важно:

- После остановки файлы документов пропадают: moto хранит их в памяти, а записи о них остаются в базе. Поэтому после любой остановки делать полный сброс (`down -v`), запуск и заполнение.
- При каждом запуске секрет для JWT новый, значит после перезапуска все входы сбрасываются. Это нормально, просто войти заново.

## 1. Веб-приложение

Общий рассказ в начале (одной фразой): «Бэкенд — это FastAPI + Postgres + S3, по заданию курса. Веб — дополнительно, на React; он ходит в тот же API, что и Swagger, ничего своего на сервере у него нет».

Где живёт: бэкенд в `src/project_hub/`, веб в `frontend/src/`. Каждая папка бэкенда — одна тема: `auth`, `users`, `projects`, `documents`, `storage`.

### 1.1 Регистрация и вход

Скриншоты: [регистрация](demo/01-register-mismatch.jpeg), [неверный пароль](demo/02-login-wrong-password.jpeg).

- **Кликнуть:** «Create one» → ввести логин, два разных пароля → «Create account». Показать ошибку «Passwords do not match». Потом вернуться на «Log in», ввести `anna` с неверным паролем → ошибка. Затем `anna` / `anna1234`.
- **Сказать:** «Регистрация — `POST /auth`, вход — `POST /login`. Сервер в ответ даёт JWT на 1 час. Пароль хранится не как есть, а как хеш Argon2».
- **Где в коде:** `src/project_hub/auth/router.py` (эндпоинты), `src/project_hub/auth/tokens.py` (выдача и проверка JWT), `src/project_hub/auth/passwords.py` (Argon2). В вебе — `frontend/src/auth/LoginPage.tsx`.
- **Почему так:**
  - **Argon2** — медленный алгоритм хеширования. Даже если базу украдут, подобрать пароли долго.
  - На неверный логин и на неверный пароль ответ одинаковый («Invalid login or password»). Так нельзя узнать, какие логины существуют.
  - Веб хранит токен в `sessionStorage` (память вкладки, `frontend/src/auth/tokenStore.ts`). Закрыл вкладку — вышел.

### 1.2 Список проектов и вкладки

Скриншоты: [все](demo/03-projects-all.jpeg), [мои](demo/04-projects-owned.jpeg), [доступные мне](demo/05-projects-shared.jpeg).

- **Кликнуть:** вкладки All → Owned → Shared with me.
- **Сказать:** «Это `GET /projects?role=owner|participant`. Роль считает сервер, у каждого проекта видно, кто я в нём: Owner или Participant. Список идёт страницами (`limit`/`offset`)».
- **Где в коде:** `src/project_hub/projects/router.py`, `src/project_hub/projects/repository_orm.py` и `repository_sql.py`; в вебе `frontend/src/projects/ProjectsPage.tsx`.
- **Почему так:**
  - Вкладка — это часть адреса (`?role=owner`). Можно обновить страницу или дать ссылку — откроется та же вкладка.
  - Два способа ходить в базу: через ORM (SQLAlchemy) и чистым SQL (psycopg). Переключаются настройкой `APP_DB_BACKEND`. **ORM** — библиотека, которая превращает строки таблиц в объекты Python. Тесты гоняются на обоих.

### 1.3 Создать и изменить проект

Скриншоты: [диалог](demo/06-project-create-dialog.jpeg), [новый проект](demo/07-project-page-new.jpeg), [после правки](demo/08-project-edited.jpeg).

- **Кликнуть:** «New project» → имя «Демо для ментора», описание → «Create project». Откроется страница проекта. «Edit» → поменять описание → «Save changes».
- **Сказать:** «Создание — `POST /projects`, правка — `PUT /project/{id}/info`. Кто создал, тот владелец».
- **Где в коде:** `src/project_hub/projects/service.py` (`create_project`, `update_project`); в вебе `frontend/src/projects/ProjectDialog.tsx`.
- **Почему так:** правила (кто что может) живут в `service.py`, а не в роутере. Роутер только принимает запрос и отдаёт ответ, поэтому правила легко тестировать отдельно.

### 1.4 Страница проекта

Скриншот: [страница владельца](demo/15-owner-project-members.jpeg), [страница участника](demo/16-participant-project.jpeg).

### 1.5 Участники: пригласить, удалить, выйти

Скриншоты: [нет такого логина](demo/09-invite-unknown-login.jpeg), [vera добавлена](demo/10-invite-vera.jpeg), [удалить vera?](demo/11-remove-vera-dialog.jpeg), [удалена](demo/12-vera-removed.jpeg), [выйти?](demo/17-leave-dialog.jpeg), [после выхода](demo/18-after-leave.jpeg).

- **Кликнуть:** в «Демо для ментора» в поле «Invite by login» ввести `nobody` → «Invite» → «No user with that login». Ввести `vera` → «Invite». Потом «Remove» у vera → подтвердить.

- **Сказать:** «Пригласить — `POST /project/{id}/invite?user=login`. Удалить и выйти — один эндпоинт `DELETE /project/{id}/members/{user_id}`: если id свой — это выход, если чужой — удаление, и его может сделать только владелец. Владелец выйти не может».

- После выхода anna больше не участник «Поездки». Чтобы вернуть: `python3 docs/frontend/demo/seed.py --documents` (boris пригласит её снова).

Если F4 не успеет — документы показать в Swagger (раздел 2.4): API для них уже есть в `main`.

### 1.7 Удалить проект

Скриншоты: [подтверждение](demo/13-delete-project-dialog.jpeg), [после удаления](demo/14-project-deleted.jpeg).

- **Кликнуть:** в «Демо для ментора» → «Delete project» → ввести имя проекта → подтвердить.
- **Сказать:** «`DELETE /project/{id}`, только владелец. Удаляются проект, участники, записи о документах и сами файлы в S3».
- **Где в коде:** `delete_project` в `src/project_hub/projects/service.py`; в вебе `frontend/src/projects/DeleteProjectDialog.tsx`.
- **Почему так:** сначала удаляется запись в базе, потом файлы. Если S3 вдруг не ответит, пользователь всё равно получит «удалено», а лишний файл просто останется в хранилище (это безопаснее, чем запись о файле, которого нет).

### 1.8 Профиль и смена пароля

Скриншоты: [неверный текущий](demo/19-password-wrong-current.jpeg), [пароль сменён](demo/20-password-changed.jpeg).

- **Кликнуть:** «Profile» → ввести неверный текущий пароль → ошибка. Потом верный: текущий `anna1234`, новый — любой от 8 символов → «Change password».
- **Сказать:** «`PUT /users/me/password`. После смены все старые токены перестают работать — на других устройствах тебя выкинет. Эта вкладка получает новый токен и остаётся в системе».
- **Где в коде:** `change_password` в `src/project_hub/auth/service.py`; в вебе `frontend/src/profile/ChangePasswordForm.tsx`.
- **Почему так:** у пользователя есть счётчик `token_version`, он записан и в токен. Смена пароля и выход увеличивают счётчик, и все токены со старым номером сервер отвергает.
- После показа вернуть пароль `anna1234` в профиле (или сделать сброс).

### 1.9 Выход и истёкшая сессия

Скриншоты: [вышла](demo/21-logged-out.jpeg), [сессия истекла](demo/22-session-expired.jpeg).

- **Кликнуть:** «Log out» → страница входа «You are logged out».
- **Как показать истёкшую сессию:** войти, открыть инструменты разработчика (F12) → Application → Session Storage → поменять значение `project-hub.token` на любую строку → кликнуть «Profile». Приложение покажет «Your session expired. Log in again.»
- **Сказать:** «`POST /logout` гасит все токены (тот же `token_version`). Если сервер ответил 401 на любой запрос, веб сам стирает токен и отправляет на вход с понятным сообщением. Через час то же самое происходит само».
- **Где в коде:** `frontend/src/api/client.ts` (реакция на 401), `frontend/src/auth/LoginPage.tsx` (сообщения).

### 1.10 Как веб связан с API (если спросят)

- **Где:** `frontend/nginx/default.conf`, `frontend/compose.yml`.
- nginx отдаёт собранный React и пересылает `/api/...` в контейнер API. Браузер видит один адрес, поэтому не нужен **CORS** (разрешение браузеру ходить на другой домен).
- В каждом ответе есть заголовки безопасности: **CSP** (какие скрипты можно запускать), `X-Content-Type-Options`, `Referrer-Policy`.

## 2. Swagger

Адрес: <http://127.0.0.1:8020/docs>. Скриншот: [общий вид](demo/23-swagger-overview.jpeg).

### 2.1 Получить токен и нажать Authorize

Скриншоты: [вход](demo/24-swagger-login-token.jpeg), [Authorize](demo/25-swagger-authorize.jpeg), [GET /users/me](demo/26-swagger-users-me-200.jpeg).

1. Раскрыть `POST /login` → «Try it out» → в теле `{"login": "anna", "password": "anna1234"}` → «Execute».
2. Скопировать `access_token` из ответа (без кавычек).
3. Наверху «Authorize» → вставить токен → «Authorize» → «Close». Замочки на эндпоинтах закрылись.
4. `GET /users/me` → «Try it out» → «Execute» → 200 и данные anna.

Сказать: «Swagger сам добавляет заголовок `Authorization: Bearer <токен>` — видно в блоке Curl».

### 2.2 Какие эндпоинты показать

- `GET /projects` с `role=owner` — тот же список, что во вкладке веба.
- `POST /projects` — создать проект руками.
- `GET /project/{project_id}/members` — участники (id проекта взять из ответа `GET /projects`).
- `POST /project/{project_id}/invite` с `user=vera`.
- `GET /health` — без токена, для проверки, что сервис жив.

### 2.3 Как выглядят ошибки

Все ответы ниже сняты с демо-стенда.

| Код | Что значит | Как получить в Swagger | Ответ |
|---|---|---|---|
| **401** | не вошёл или токен плохой | «Logout» в окне Authorize, потом `GET /projects`; или `POST /login` с неверным паролем | `{"detail":"Not authenticated"}`, `{"detail":"Invalid login or password"}` |
| **403** | вошёл, но прав нет | войти как `boris`, взять id «Дипломный проект», вызвать `DELETE /project/{id}` | `{"detail":"Only the project owner can delete the project"}` |
| **404** | нет такого или нет доступа | войти как `vera` и запросить `GET /project/{id}/info` проекта anna | `{"detail":"Project not found"}` |
| **422** | неверный формат запроса | `POST /auth` с `{"login":"x","password":"123","repeat_password":"123"}`; или `project_id` = `abc` | список полей с ошибками: `string_too_short`, `uuid_parsing` |
| **409** | конфликт | `POST /auth` с логином `anna` | `{"detail":"Login 'anna' is already taken"}` |

Сказать про 403 и 404: «403 — когда ты в проекте, но действие только для владельца. 404 — когда ты не в проекте вообще: мы не подтверждаем, что такой проект есть».
Про 422: «FastAPI проверяет запрос по схемам Pydantic ещё до моего кода и сам пишет, какое поле не так».

### 2.4 Документы в Swagger

- `POST /project/{project_id}/documents` → «Try it out» → выбрать `docs/frontend/demo/files/meeting-notes.pdf` → «Execute» → 201.
- `GET /project/{project_id}/documents` — список.
- `GET /document/{document_id}` — скачать (в ответе Swagger появится ссылка на файл).
- `PUT /document/{document_id}` — заменить на `meeting-notes-v2.pdf`.
- `DELETE /document/{document_id}` — 204.
- Ошибка формата: загрузить любой `.txt` → 422 «only pdf and docx documents are allowed».
- **Где в коде:** `src/project_hub/documents/router.py`, `validation.py` (проверка файла), `src/project_hub/storage/s3.py` (S3).
- **Почему так:** тип файла проверяется по содержимому, а не только по расширению: PDF начинается с `%PDF-`, DOCX — это zip с `word/document.xml`. Переименованный `.exe` не пройдёт. Предел — 10 МБ на файл.

## 3. Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Порт занят (`port is already allocated`) | В команде запуска поменять число: `WEB_PORT=8101` или `APP_PORT=8021`. Для заполнения тогда `python3 docs/frontend/demo/seed.py --documents --api http://127.0.0.1:8021`. Кто занял порт: `lsof -iTCP:8100 -sTCP:LISTEN`. |
| Стенд не отвечает | `docker compose -p demo -f docker-compose.yml -f frontend/compose.yml ps` — все ли `healthy`. Логи API: `docker compose -p demo -f docker-compose.yml -f frontend/compose.yml logs api --tail 50`. Если Docker Desktop не запущен — запустить его и выполнить «Запуск». |
| Данные перепутались, удалила не то | Полный сброс: `down -v`, «Запуск», «Заполнить» (раздел 0). Около 3 минут. |
| Веб пишет «Your session expired» | Нормально после перезапуска стенда или через час. Войти заново. |
| Swagger пустой (белая страница) | Нет интернета: Swagger грузит скрипты с CDN. Показать скриншоты 23–26 из `docs/frontend/demo/` или `curl` из таблицы 2.3. |
| Документ не скачивается после перезапуска | Файлы в moto пропали при остановке. Полный сброс. |

## 5. Что заметили при прогоне

Прогон 16.11.2026 ночью, скриптом `demo/walk.mjs` (Chromium, 1280×800). Весь сценарий прошёл без ошибок.

Повторить прогон (нужны `npm ci` в `frontend/` и `npx playwright install chromium`; скрипт сам возвращает данные как были):

```bash
node docs/frontend/demo/walk.mjs
```

- **Шрифт русских названий (веб, косметика).** Заголовок проекта набран шрифтом Space Mono, а в нём нет кириллицы. Русское название рисуется запасным шрифтом с засечками и широкими пробелами («Дипломный  проект»). Работе не мешает. Если спросят: «шрифт подберём с кириллицей».
- **Стопка уведомлений на скриншотах (не баг).** Зелёные уведомления сами исчезают через 5 секунд (проверено). На скриншотах их много, потому что скрипт кликает быстрее. Пока над уведомлением курсор, оно не исчезает — так задумано, чтобы успеть прочитать.
- **Текст ошибки короткого пароля в API (бэкенд, косметика).** В 422 на пароль короче 8 символов сообщение «Value should have at least 8 items after validation, not 3» — звучит странно («items»). В вебе свой понятный текст.
- **В Swagger не описаны 401/403/404/409 (бэкенд, документация).** У эндпоинтов в списке ответов только 200 и 422; остальные коды работают, но в схеме не перечислены.
