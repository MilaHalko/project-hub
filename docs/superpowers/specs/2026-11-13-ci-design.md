# Epic 2: CI on GitHub Actions

Date: 2026-11-13
Status: approved design
Roadmap: [`docs/PRDs/roadmap.md`](../../PRDs/roadmap.md), epic 2

## Goal

Every pull request and every push to `main` is checked automatically on GitHub:
lint, type check, tests on a real Postgres for both DB backends, and the Docker
image is built and run. Spec, stack: "CI/CD: GitHub Actions
(testing/linting/building/...)". Pushing to a registry and deploying are epic 8.

## Decisions

| Area | Decision | Why |
|---|---|---|
| Files | One workflow, `.github/workflows/ci.yml`, two jobs: `checks` and `docker` | Small enough for one file; epic 8 adds a `deploy` job that `needs` both |
| Both backends | One plain `pytest` run, then a step that fails unless `*_contract.py` tests passed with both `[orm]` and `[sql]` ids | The `database` fixture already parametrizes every contract test over both backends; an `APP_DB_BACKEND` matrix would run the same tests twice |
| Test database | GitHub `services:` Postgres, image `postgres:18-alpine` (same as compose `db`), `TEST_DATABASE_URL=postgresql://project_hub:project_hub@localhost:5432/postgres` | Same server version as local development; test-only credentials, no secrets |
| Python | `actions/setup-python` with `python-version-file: .python-version` (3.13) | One source of truth; local venvs run 3.15, CI is where 3.13 is checked |
| Poetry | `pipx install poetry==2.5.1`, the version pinned in `Dockerfile` | CI and image build the same way |
| Cache | `setup-python` cache for Poetry, keyed on `poetry.lock` | Faster runs |
| Docker | Job `docker` runs `poetry run pytest -m docker` (existing smoke tests: image as non-root, compose stack, `migrate` creates `users`) in parallel with `checks` | Builds the image the roadmap asks for and proves `db → migrate → api` works; what epic 8 deploys is already tested |
| Token | Top-level `permissions: contents: read`, no job widens it | A compromised step cannot write to the repo |
| Third-party actions | Pinned to full 40-character commit SHAs, version in a comment | Tags can be moved to other code; SHAs cannot |
| Cost | `concurrency` cancels the older run of the same ref; every job has `timeout-minutes` | No duplicate or hung runs |
| AWS | Nothing: no credentials, no `secrets.*`, no ECR, no deploy | Epic 8 |
| Dependabot | Not added | Extra PR noise for a course project; can be added later |
| Branch protection | Not part of the code; offered after the first green PR | GitHub can require only checks it has already seen |

## Workflow

```
on: pull_request (any branch) | push to main
 ├── checks: checkout → Python 3.13 → Poetry 2.5.1 → poetry install
 │           → ruff check → ruff format --check → pyright
 │           → pytest -v (Postgres service) → assert [orm] and [sql] contract tests passed
 └── docker: checkout → Python 3.13 → Poetry 2.5.1 → poetry install → pytest -m docker
```

## Testing

`tests/test_ci_workflow.py` parses `ci.yml` with PyYAML and pins the decisions
above. PyYAML is already installed (via `uvicorn[standard]`) but is added to the
dev group explicitly, with `types-PyYAML` for pyright strict.

## Acceptance criteria

Proven by `tests/test_ci_workflow.py`:

1. Triggers: `pull_request` and `push` limited to `main`.
2. `concurrency` with `cancel-in-progress`; every job has `timeout-minutes`.
3. Top-level `permissions` is exactly `contents: read`; no job sets `permissions`.
4. Every `uses:` is pinned to a 40-character hex SHA.
5. Both jobs set up Python from `.python-version` (which is `3.13`) and install
   the Poetry version pinned in `Dockerfile`.
6. Job `checks` runs `ruff check`, `ruff format --check`, `pyright`, `pytest`
   in that order.
7. Job `checks` has a Postgres service with the compose `db` image and sets
   `TEST_DATABASE_URL` with an explicit host and port.
8. Job `checks` fails unless contract tests passed with both `[orm]` and `[sql]`.
9. Job `docker` runs `pytest -m docker` and does not `need` `checks`.
10. The workflow mentions no `aws`, `ecr`, `secrets.` or deploy step.

Proven on GitHub:

11. In the PR against `main`, both `checks` and `docker` are green.
12. The `checks` log shows contract tests passing with `[orm]` and `[sql]`.
