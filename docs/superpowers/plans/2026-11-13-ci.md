# Epic 2: CI on GitHub Actions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions workflow that lints, type-checks and tests every PR and every push to `main`, on real Postgres for both DB backends, and builds and runs the Docker image.

**Architecture:** One workflow file with two parallel jobs, `checks` and `docker`. A small, unit-tested helper reads the verbose pytest log and fails unless contract tests passed for both backends. A pytest module parses the workflow YAML and pins every design decision.

**Tech Stack:** GitHub Actions, Poetry 2.5.1, Python 3.13, PyYAML, pytest, Postgres 18-alpine.

**Spec:** [`docs/superpowers/specs/2026-11-13-ci-design.md`](../specs/2026-11-13-ci-design.md)

> **Superseded in part (2026-11-13):** after implementation, the project adopted "tests prove
> behaviour only". `tests/test_ci_workflow.py`, `tests/support/test_backend_coverage.py`, the
> PyYAML dev deps and the `compose_config` move were removed (commit 8da2007). The criteria are
> proven by the workflow file and its green GitHub run; see the spec.

## Global Constraints

- Python version comes from `.python-version` (`3.13`); never hard-code it in the workflow.
- Poetry version in CI equals the `poetry==` pin in `Dockerfile` (`2.5.1`).
- Postgres image in CI equals the compose `db` image (`postgres:18-alpine`).
- Third-party actions pinned by full SHA, version in a trailing comment:
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`
  - `actions/setup-python@6d4fd22b20465ccc0f7354476588e8df7c9ca0e0 # v7.1.0`
- Token: top-level `permissions: {contents: read}` only. `actions/checkout` with `persist-credentials: false`.
- No AWS, no `secrets.`, no ECR, no deploy (epic 8).
- Never add a `Co-Authored-By: Claude` trailer to commits.
- pyright strict, ruff (line length 100), `poetry run` for every tool.

## Review Focus

1. A pipe hides a failing pytest (`pytest | tee` returns tee's status). Expected: `checks` is red when pytest fails. Pinned by the workflow test requiring `defaults.run.shell: bash` (GitHub then runs `bash -eo pipefail`).
2. Poetry builds the venv on the runner's system Python instead of 3.13. Expected: CI runs on 3.13. Pinned by a workflow step that asserts `sys.version_info[:2] == (3, 13)` inside `poetry run`, and a test that the step exists.
3. A contract test fails or is skipped for one backend while the other passes. Expected: the backend check reports that backend missing. Pinned by helper tests with FAILED / SKIPPED lines.
4. Non-contract tests carry `[orm]` ids too (`tests/test_config.py`, `tests/db/test_database_factory.py`). Expected: they do not count. Pinned by a helper test.
5. The pytest log file is missing (pytest crashed before writing). Expected: the helper exits non-zero with a clear message, not a traceback. Pinned by a helper test.

### Task 1: Backend coverage helper

**Files:**
- Create: `tests/support/backend_coverage.py`
- Test: `tests/support/test_backend_coverage.py`

**Interfaces:**
- Produces:
  - `BACKENDS: Final = ("orm", "sql")`
  - `missing_backends(log: str, backends: Sequence[str] = BACKENDS) -> list[str]` — backends (in input order) with no line matching `<path>_contract.py::<name>[<backend>] PASSED` in a `pytest -v` log.
  - `main(argv: Sequence[str] | None = None) -> int` — `argv[0]` is the log path; prints `contract tests passed for: orm, sql` and returns 0, or prints `no passing contract tests for: <names>` / `pytest log not found: <path>` to stderr and returns 1. Module runs as `python -m tests.support.backend_coverage <log>`.

Real log line format (from this repo):
`tests/users/test_repository_contract.py::test_add_returns_user_with_generated_fields[orm] PASSED [  8%]`

- [ ] **Step 1: Write the failing tests** in `tests/support/test_backend_coverage.py`:

  - `test_missing_backend_is_reported` — only `[orm] PASSED` → `["sql"]`.
  - `test_failed_or_skipped_do_not_count` — `[sql] FAILED` and `[sql] SKIPPED` lines plus `[orm] PASSED` → `["sql"]`.
  - `test_non_contract_tests_do_not_count` — `tests/test_config.py::test_backend_accepts_valid_value[orm] PASSED` and the same for `sql`, nothing else → `["orm", "sql"]`.
  - `test_main_ok` (uses `tmp_path`, `capsys`) — valid log → returns 0, stdout contains `orm, sql`.
  - `test_main_reports_missing` — log without sql → returns 1, stderr contains `sql`.
  - `test_main_missing_file` — path that does not exist → returns 1, stderr contains `not found`.

### Task 2: Workflow, its tests, dev deps, README

**Files:**
- Modify: `pyproject.toml`, `poetry.lock` (via `poetry add --group dev pyyaml types-pyyaml`)
- Create: `.github/workflows/ci.yml`
- Create: `tests/test_ci_workflow.py`
- Modify: `README.md` (new `## CI` section after `## Checks`)

**Interfaces:**
- Consumes: `python -m tests.support.backend_coverage <log>` from Task 1 (exit 0 / 1).

Workflow shape (the implementer writes the YAML):

```
name: CI
on: pull_request | push: branches [main]
permissions: contents: read
concurrency: group ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true
defaults: run: shell: bash
jobs:
  checks (ubuntu-latest, timeout-minutes 15)
    services.postgres: image postgres:18-alpine, env POSTGRES_USER/PASSWORD/DB = project_hub,
      ports 5432:5432, health options (pg_isready, interval 2s, timeout 3s, retries 15)
    env TEST_DATABASE_URL: postgresql://project_hub:project_hub@localhost:5432/postgres
    steps: checkout (persist-credentials false) → pipx install poetry==2.5.1
      → setup-python (python-version-file .python-version, cache poetry)
      → poetry install --no-interaction
      → poetry run python -c "import sys; assert sys.version_info[:2] == (3, 13), sys.version"
      → poetry run ruff check → poetry run ruff format --check → poetry run pyright
      → poetry run pytest -v 2>&1 | tee pytest.log
      → poetry run python -m tests.support.backend_coverage pytest.log
  docker (ubuntu-latest, timeout-minutes 20, no `needs`)
    steps: checkout → pipx install poetry==2.5.1 → setup-python (same) → poetry install
      → poetry run pytest -m docker -v
```

Note: PyYAML parses the key `on` as boolean `True`; the test reads `workflow.get("on", workflow.get(True))`.
