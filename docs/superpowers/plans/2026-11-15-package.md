# Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `poetry build` makes a wheel and an sdist of `project_hub`; CI builds them on every PR, uploads them, and proves that the wheel works when installed on its own.

**Architecture:**
- One opt-in pytest file `tests/test_package_smoke.py` (marker `package`) installs the built wheel into a clean virtualenv and runs it from another folder.
- A new CI job `package` builds, uploads the artifact and runs that file on the uploaded files.
- Nothing in `src/` changes except the new console command (Task 4).

**Tech Stack:** Poetry 2.5.1 (`poetry-core` build backend), pip, venv, uvicorn, psycopg, pytest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-15-package-design.md` (read it; criteria numbers below refer to it).

## Global Constraints

- **Names.** Marker `package`; env variable `PACKAGE_DIST_DIR`; CI job `package`; artifact `project-hub-dist`, retention 14 days; console command `project-hub-migrate`.
- **Do not rename, remove or change** the jobs `checks` and `docker`. Do not touch `Dockerfile`, `docker-compose.yml`, `poetry.lock`, `frontend/`.
- **Clean install.** The virtualenv and the working folder of every command are in a temporary folder; every command runs `-I` (isolated mode). Nothing from `src/` or `.env` may leak in.
- **Tests need Postgres** for the migration test: `TEST_DATABASE_URL`, default `DEFAULT_ADMIN_URL` from `tests/support/database.py` (compose `db` on port 55433). Use `create_test_database` and `drop_test_database` from there.
- **No tests that re-read** `pyproject.toml` or workflow files. Metadata is proven by `poetry check --lock` and `poetry build`.
- **Third-party actions** are pinned to a full commit SHA with the version in a comment. Use `actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2` (the same line as in `frontend.yml`).
- **Comments.** None, and no docstrings, unless one explains a hidden reason that makes code unsafe to change. Never delete an existing comment. Check the diff for new `#` and `"""` lines before committing.
- **Commits.** One per task, subject in plain words, no `Co-Authored-By`, no Claude attribution.

## Review Focus

1. **The test passes by accident from `src/`.** The imported module path must be inside the venv's `site-packages` → Task 1.
2. **A migration file is missing from the wheel.** The installed `alembic_version` must equal the head of the source tree, not a hard-coded number → Task 2.
3. **The uploaded artifact differs from what is tested.** CI passes `PACKAGE_DIST_DIR=dist`, the same folder that was uploaded → Task 1.
4. **A leftover server or database after a failed test.** The uvicorn process is killed and the test database dropped in `finally` → Tasks 1 and 2.
5. **The default `pytest` becomes slow.** Package tests stay deselected without `-m package` → Task 1.

### Task 1: Prove the built wheel serves `/health` (criteria 1, 2, 3, 8, 9, 10)

**Files:**
- Create: `tests/test_package_smoke.py`
- Modify: `pyproject.toml` (`[tool.pytest.ini_options]`: marker `package`, `addopts` → `-m "not docker and not package"`)
- Modify: `.github/workflows/ci.yml` (new job `package` after `docker`)
- Modify: `README.md` (section "Build the package": `poetry build`, `pip install dist/*.whl`, `pytest -m package`)

**Interfaces:**
- Produces: session fixtures in the test file that Tasks 2-4 reuse: `dist_dir() -> Path`, `wheel(dist_dir) -> Path`, `sdist(dist_dir) -> Path`, `venv_python(wheel, tmp_path_factory) -> Path`, and `run_installed(venv_python, *args, env=None) -> CompletedProcess[str]` (isolated, temporary cwd, no `APP_*` variables inherited).

- [ ] **Step 1: Write the tests**
  - `test_build_makes_wheel_and_sdist`: `wheel.name` is `project_hub-<v>-py3-none-any.whl`, `sdist.name` is `project_hub-<v>.tar.gz`.
  - `test_installed_package_comes_from_site_packages`: `python -I -c "import project_hub; print(project_hub.__file__)"` prints a path inside the venv's `site-packages` and not under the repository `src/`.
  - `test_installed_app_serves_health`: start `python -I -m uvicorn project_hub.main:app --host 127.0.0.1 --port <free port>`; poll `GET /health` until 200; assert body `{"status": "ok"}`; terminate the process in `finally`.
- [ ] **Step 2: Run** `poetry run pytest -m package -v` → fails (marker unknown).
- [ ] **Step 3: Implement** the marker and `addopts` in `pyproject.toml`; `dist_dir` uses `PACKAGE_DIST_DIR` if set, otherwise runs `poetry build -o <tmp>`; the venv is made with `sys.executable -m venv`, the wheel installed with its `pip`.
- [ ] **Step 4: Run** `poetry run pytest -m package -v` → passes; `poetry run pytest -q` → package tests deselected.
- [ ] **Step 5: CI job `package`.** Same Python, Poetry and checkout steps as `docker`, then `poetry build`, upload `dist/*` (`if-no-files-found: error`), then `PACKAGE_DIST_DIR=dist poetry run pytest -m package -v`. `timeout-minutes: 15`.
- [ ] **Step 6: Commit** "Build a wheel and sdist in CI and prove the installed wheel serves /health".
