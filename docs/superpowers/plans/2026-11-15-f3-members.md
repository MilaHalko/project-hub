# F3 Members and Invites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native, chosen by the user for frontend epics, PR #18) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A members panel on the project page with invite by login (owner), remove a participant (owner) and leave a project (participant).

**Architecture:** A new `frontend/src/members/` folder holds the panel, the invite form and the two confirmation dialogs; `api/members.ts` wraps the three endpoints. `ProjectPage` gets a two-column body (details left, members right) and the "Leave project" banner action. Members live in the query `["members", projectId]`; who sees which control is decided by the project's `my_role`.

**Tech Stack:** React 19, TypeScript, TanStack Query, React Router, CSS modules, Vitest + Testing Library, Playwright with `@axe-core/playwright`.

**Spec:** [`docs/frontend/specs/2026-11-15-f3-members-design.md`](../../frontend/specs/2026-11-15-f3-members-design.md), mockup [`docs/frontend/mockups/f3-members.html`](../../frontend/mockups/f3-members.html).

## Global Constraints

- Only `frontend/` and `docs/` frontend files change; no backend file (`src/`, `tests/`, `pyproject.toml`, `poetry.lock`, root `Dockerfile`, `docker-compose.yml`, `.github/workflows/ci.yml`).
- No comments or docstrings unless the code looks safe to change but is not; check every diff for new `//`, `/*`, `#` lines.
- Copy exactly as in the spec: sentence case, no "please", no "successfully", no exclamation marks.
- Every e2e test creates its own users via `createUser`/`signIn`; every visited page and open dialog passes `expectAccessible`; a test expecting a 4xx sets `test.use({ expectedApiStatuses: [...] })`.
- One commit per task (a user-visible slice), plain-words imperative subject, no `Co-Authored-By` trailer.
- Checks per task: `npm run lint`, `npm run typecheck`, `npx vitest run <files>`; e2e: `E2E_BASE_URL=http://127.0.0.1:8093 npx playwright test <spec>` against the `f3members` stack.

## Review Focus

1. Login typed with spaces around it (" sam ") → sent as `sam` (Task 2 test).
2. Enter pressed twice while an invite is pending → one request (Task 2 test).
3. Members request answers 404 after the project loaded (owner deleted it meanwhile) → panel shows "Couldn't load the members.", banner and details stay (Task 1 test).
4. "Leave project" confirmed while `GET /users/me` has not answered → no `DELETE` with an empty id; the button is busy (Task 4 test).
5. A 32-character login at 375 px → wraps inside the panel, the page does not scroll sideways (Task 1 e2e, phone project).
